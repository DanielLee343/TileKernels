# 专家算子 Profiling Excel 规格

交付两份 Excel。两份都覆盖相同的采集目标，分别回答「每个核测到了什么」和「整个 kernel 测到了什么」。

| 文件名 | 行粒度 |
|---|---|
| `专家算子Profiling-逐核明细版.xlsx` | 每个目标先有一行采集信息，随后是该次采集的逐核行。 |
| `专家算子Profiling-采集精简版.xlsx` | 每个目标只占一行，保留有明确汇总口径的指标。 |

两份文件均放在 `docs/`，按原文件名覆盖更新。两个文件都包含 `Vector`、`Cube` 和 `CV融合` 三张表。按 `OpBasicInfo.csv` 中实测的 `Op Type` 选择工作表。混合 kernel 只在 `CV融合` 出现一次，指标按 AIC 和 AIV 分别列出。表头包含指标单位，汇总列在表头同时写明公式。数据区使用筛选和冻结表头，数值单元格使用数值类型。

## 1. 选取采集记录

- 一个目标由输入 case 和实际目标 kernel 确定。同一调用中有两个同名 kernel 时，用调用角色或顺序区分。例如同一 RoPE 输入的 Q 和 K 各是一个目标。
- 每个目标只选最新一份已验收且原始数据可用的采集。两个工作簿必须选中同一窗口，任务耗时和复算分母都取该窗口。失败尝试和历史版本留在归档。
- 数据行保留目标 ID、case 名、目标 kernel、输入和配置、数据集、窗口序号、任务耗时、Block Dim、Mix Block Dim、设备及健康状态、采集方式、验收与复算状态、原始采集路径、对账证据。输入和配置保留 shape、dtype 以及影响执行的布局、标志和参数。
- 验收状态要能区分原版专家实现、正确性参考的口径、原始数据是否可用及搬出字段是否完成核对。自己改写的 kernel 作为单独的实验资料。自己定义输入后调用官方原版 kernel 的采集可以入表，并保留输入来源。

## 2. 逐核明细版

每个目标的首行标为「采集」，显示任务耗时和采集信息。随后每个 `(block_id, sub_block_id)` 一行，标为「逐核」，并标出核侧 `AIC` 或 `AIV`。核耗时和活动时间放在逐核行，任务耗时放在采集行。

- 从同一窗口的 `OpBasicInfo`、`ArithmeticUtilization`、`L2Cache`、`Memory`、`MemoryL0`、`MemoryUB`、`PipeUtilization`、`ResourceConflictRatio` 读取。逐核表通过 `block_id` 和 `sub_block_id` 对齐，检查各表的核集合一致。保留适用核侧的原始字段名、单位、原值和工具原始 `NA`。
- 向量核搬出另列六项复算结果。前两项是 **UB→GM 请求字节**和**工具计入的 UB 侧字节**。后四项是 `aiv_ub_to_gm_bw`、`aiv_ub_read_bw_gm`、`aiv_mte3_active_bw` 和 `UB_to_GM_bw_usage_rate` 的复算值。原始工具列继续保留。
- 前两项需要同一窗口的地址记录与逐核核对，或经核对的原始二进制、指令数和搬出长度。请求字节按有效请求计。UB 侧按工具针对该指令的计量规则计算，包含适用的对齐取整。`write_main_memory_datas` 作为独立的原始主存写计数保留。
- 两个逐核任务带宽列以该核计入的 UB 侧字节为分子。纯 Vector 窗口用核周期除以 MHz 得到该核耗时，混合窗口用任务耗时。活跃带宽用该核 MTE3 活动时间作分母。换算为 GiB/s 时，`B ÷ µs × 10⁶ ÷ 2³⁰`。现有 950PR 表的逐核利用率按 `min(100, 100 × 复算任务带宽 ÷ 131.76)` 复算，其他平台需先确认该通路和峰值的口径。

## 3. 采集精简版

每个目标一行。保留第 1 节的采集信息。纯 Vector 只汇总 AIV，纯 Cube 只汇总 AIC，CV 融合在同一行分别汇总两侧。汇总均从该目标在明细版选中的核行计算。

| 列组 | 计算口径 |
|---|---|
| 核记录数、最慢核耗时、核周期 | 核记录数为该侧核行数，最慢核耗时取最大值，核周期求和。 |
| 搬运量、主存读写、指令数 | 对各核的同名字段求和，保留搬运通路和核侧。AIV 包括 GM→UB 和 MTE2/MTE3 指令。AIC 包括 GM→L1、L0C→GM、L0C→L1，及 Cube、MTE1/MTE2/MTE3 指令。 |
| 流水活动时间 | 对该侧各核的同一流水活动时间求和，单位为核·µs。AIV 汇总 Vector、Scalar、MTE2、MTE3。AIC 汇总 Cube、Scalar、MTE1、MTE2、MTE3、FixPipe。 |
| 活动、等待和冲突比率 | 对有原始核周期分母的比率用 `Σ(核比率 × 核周期) ÷ Σ核周期`。保留原口径的 `0–1` 或 `%`。 |
| L2 命中率 | read/write 各算一次。先分别汇总 close/far 的 hit、miss、victim，再算 `100 × Σhit ÷ Σ(hit + miss + victim)`。保留各类计数列。 |
| 有搬运量的任务带宽 | `Σ搬运 KiB × 10⁶ ÷ (2²⁰ × 任务耗时 µs)`。MTE2 活跃带宽将分母换成同侧各核 MTE2 活动时间之和。 |
| 只有逐核带宽的任务带宽 | 核实工具原分母后，用 `Σ(核带宽 × 原分母) ÷ 任务耗时`，表头标「约」。当前 950PR 的纯核采集用核耗时，混合采集用任务耗时。分母未确认或为 KernelScale 时留空。 |
| AIC MTE1、MTE3、FixPipe 活跃带宽 | `Σ(核活跃带宽 × 该流水核活动时间) ÷ Σ该流水核活动时间`，表头标「约」。该口径要求参与核的带宽和活动时间均有效，且活动时间为正。 |
| AIV 向量核搬出四列 | `Σ请求 B`、`Σ工具计入 UB 侧 B`、`ΣUB 侧 B ÷ 任务耗时`、`ΣUB 侧 B ÷ Σ各 AIV 的 MTE3 活动时间`。两种带宽都换算为 GiB/s。 |

I-cache 命中或缺失比率等没有可验证全局分母的指标，以及没有统一全局峰值口径的利用率，保留在逐核版。

## 4. 缺值和交付检查

- `0` 表示已取得且值为零。保留工具原始 `NA`。无法计算的派生值留空，并用状态列说明「不适用」「缺原始字段」「未对账」或「分母为零或缺失」。汇总需要该核侧完整的一组数据，缺值时保留原样。
- 核对两份文件的 `(目标 ID, 采集来源, 窗口序号)` 一一对应。汇总版每个目标仅一行，明细版每个目标仅一行采集信息和一套不重复的核行。
- 逐项检查汇总的分子、分母、单位和缺值与原始数据一致。核对三张表、目标数、核行数、表头和文件可读性。记录未入表的目标与原因。
- 当前快照有 1,290 个采集目标，Vector 1,174 个、Cube 34 个、CV融合 82 个。逐核版另有 70,773 条核行。新增采集后以新的验收台账为准。 [当前数据台账](https://github.com/DanielLee343/TileKernels/tree/622ec146b8743d4e0d1a76d9c8c99dabed74a4b0/research/ascend-profiling/backfill-20261109/official-followup-20261111)
