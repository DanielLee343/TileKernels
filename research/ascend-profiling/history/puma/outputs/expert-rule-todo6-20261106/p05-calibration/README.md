# P05 独立 case 离线标定：预发布框架

当前结论：**参考不足，尚无可输出的 P05 边界候选。** 本目录实现固定公式、分组和 case 级统计的计算部件；真实 A/B 验收器只能以开发身份接入，独立校准 case 的同次原表身份与适用性准入接口尚未建立，不能把自填数字当作合格证据。没有读取留出或客户指标，不自动 promotion。

## 固定合同与注册

命令接受 UTF-8 JSON 登记册及其预先固定的 SHA256：

```powershell
python -B outputs/expert-rule-todo6-20261106/p05-calibration/calibrate.py <registry.json> --freeze-sha256 <sha256> [--ab-root <已采A_B根目录>]
python -B -m unittest discover -s outputs/expert-rule-todo6-20261106/p05-calibration -v
```

登记册必须有 `device`、`condition`、`formula`、`response`、`cases`。支持 `contiguous_128_v1`，即 R=128×ceil((o+L)/128)，o 为实际起始地址模 128、L 为已证明的单段连续合法输出长度；`response` 只能是 `difference`（W−R，字节）或 `ratio`（W/R−1，R>0）。公式不是旧阈值；非连续、输出分段和未知写段不可使用它。另有 `per_verified_segment_128_v1` 纯计算接口，详见下节。一个登记册固定一个设备、条件、公式及响应，禁止混池。每个 case 必须有唯一 `id`、实现 `family`、`split`；split 是 development、calibration、holdout、positive_control、negative_control。相同 family 跨 split 会被拒绝，作为独立性保守门槛；正负控制不冒充独立专家。case 任务合同、源码、二进制、profile 对应关系和族的含义仍需冻结材料独立验证，字符串不同不自动证明独立。

`--freeze-sha256` 只验证登记册此刻未被更改；它**不能证明登记册在查看指标之前已冻结**。必须另有可审计的预登记时间和名单。当前 CLI 不接受登记册自带数字作校准或留出，也不从未知适配器接收数值，因此即便填入数值也返回参考不足。可选 A/B 入口直接调用固定哈希的既有验收器，按每次同采集的原表路径、哈希和 eligible 状态列出来源，严格标为开发用途，不读取留出。验收器本身的身份和覆盖缺口仍适用。

## 统计部件与限制

`aggregate_cases` 对已由未来独立验收器核准的数据严格检查设备、公式和 capture 哈希跨 case 唯一性，计算每次 W−R 或 W/R−1；`summarize` 先按 case 保留原复采及最小/最大值。`calibrate` 演示明确预选的经验方法：每 case 至少三次，先取各 case 最大响应，再取各 case 最大值的最大值作为经验上界。只有在**事先冻结该方法**且独立校准样本均准入后才可调用；它是观察范围，不保证总体覆盖率或误报率。不能从复采次数推独立样本数，也不设旧阈值 1。缺失、重复、条件混合、零分母均拒绝；不以删除异常来生成边界。

`check_holdout` 对预先固定的上界按 case 最大响应报告实际误报 case 数、总 case 数、逐 case 标记及原复采；不返回调整后的阈值。它只适用于被独立验收为合法负例的留出，调用前须固定适用范围、名单及公式，不得先看其数字。采集控制正例另算检出，不能并入专家误报分母。没有分布假设或样本基础时不声称统计覆盖；本实现不输出置信度或总体保证。

以上计算函数是数学部件，不执行采集身份核验，也不允许它们的单元测试生成可准入证据。要实际输出边界，需要接入逐次经独立审核的真实采集器适配器：直接重算同次原表，验证 capture 文件/哈希、目标 kernel/二进制、物理设备、完整输出、合法写段、工具/采集协议及干扰证据，再与预先冻结的 case/族和用途绑定。当前 C3 是纯 Cube 控制，AIV C 与 A/B 开发不能冒充独立 AIV 校准专家。假如发现反例或更改公式，保留结果，重新冻结并另选未使用样本；不得反调留出。

本次没有上板、修改主 TODO、读取保留或客户 PMU。合成测试仅验证计算和拒绝行为，不构成采集。

## 已核验分段的参考公式

`segment_reference(segments, expected_ranges, allocation_bytes, base_offset, external_writes)` 是纯数学接口。每段为 allocation 内 `(起始字节偏移, 有效长度)`；段起始地址余数是 `(base_offset + 起始偏移) mod 128`，逐段计算 `128×ceil((余数+长度)/128)` 后相加。一个 output view 的 stride 空洞不计入有效长度；每个段独立取整，哪怕不同段触及同一 128 B 单元也不能自行去重，因为该候选的计量单位是已验证段而非缓存行并集。

接口拒绝空列表、零长度、越界、段相交或重复、缺少/多出有效范围以及外写状态不是 `none_verified`。它比较段并集与独立提供的期望有效范围，允许将连续有效范围拆成相邻段，但段边界本身会影响公式结果，必须由真实写路径独立确定。`none_verified` 和 `expected_ranges` 都是调用方声明，函数无法证明它们；真实接入须由未来同次 capture adapter 独立核实每段、offset、长度、对象与 allocation、写段完整覆盖、无重复/额外写入，并固定公式和条件。几何结果不证明硬件按段计数。

合成测试按预登记 128 行、每行 8192 B 计算 P0/P16/P32/P64 的 R 分别为 1,048,576 / 1,060,864 / 1,056,768 / 1,048,576 B。H-C 在假设首址对齐、512 行各 10,240 B、行距 10,272 B 下，逐行 R 为 5,292,032 B，整体跨度取整为 5,259,264 B；这是几何计算，不是 H-C 的 W、实际写段证明或阈值。本次没有读取 H-C 留出 W。

默认 CLI 即便登记分段公式并自填分段，仍返回 `reference_insufficient` 且无边界；合成测试不会绕过真实身份门槛。
