# M1 INT8 development sample: Cube counter cross-check

Scope: independently reviewed `expert-rule-cube-mix-m1-20261106-queue02/source-sitefix/m1/run-cases/b2` only; no new device measurement. The archived source and fixture specify eight groups of 128 rows, M=1024, K=1024, N=8192, signed INT8 x and weight, INT32 matmul intermediate followed by floating-point dequantization and activation. The captured task is MIX, eight AIC and 16 AIV. The independent M1 review records complete output comparison against archived golden and guard checks, with stated limitations.

Actual Default Arithmetic and Pipe tables have the same 24 unique `(block_id,sub_block_id)` keys. Restricting to `(0..7,cube0)`, each row has instruction fields total/fp/int `(256,0,256)`; summed tuple `(2048,0,2048)`. Each row reports FP activity ratio `0.000000`, integer activity ratio 0.660113–0.662683, Cube total ratio equal to integer ratio, and Pipe Cube activity 79.437576 microseconds. The 8-core activity sum is 635.500608 microseconds, not elapsed latency.

DeviceProf2 and DeviceProf6 each contain eight filtered Cube block PMU records, matching the eight keys. Using the locally inferred A5 layout, DeviceProf2 zero-based raw slots 4/5/6 are `(256,0,256)` for every block, exactly matching CSV total/fp/int instruction fields. DeviceProf6 raw slots 3/4/5 are `(0,131072,131072)` on every block; under the local-source event-order hypothesis these correspond to FP/int/total activity, and their ratios to that round's per-block cycle count match the CSV values at displayed precision. This is raw-to-CSV consistency; the actual collector's event IDs and validity are not independently authenticated.

For the original captured ELF, local SHA256 and read-only A5_1 SHA256 both equal `050083670df2761eca6e41cefa697c9a4a172a6d2bef18cd3df0946db3c4ae93`. A read-only disassembly using CANN 9.2.0 `llvm-objdump -d` reports `1030: f0656508 MMAD.s8 [X18], [X22], [X10], X2`. This establishes opcode presence in the captured binary, not that every path or instruction executes.

Comparison to the three previously checked FP16 cases: square and BMM active Cube rows report `(1,0,1)` and FP activity nonzero, integer activity zero; tail rows report `(6,3,3)` on 21 rows and `(6,0,6)` on four, likewise FP activity nonzero and integer activity zero. M1's integer activity and reported integer instruction classification agree with its INT8 contract; FP16 activity alongside integer instruction fields remains the observed discrepancy. This is useful conditional evidence but M1 is mixed execution, has a different kernel and workload, and is not a fixed pure Cube FP/int control. It cannot establish counter semantics, physical event availability, issued FLOPs, or a cause for the FP16 discrepancy.
