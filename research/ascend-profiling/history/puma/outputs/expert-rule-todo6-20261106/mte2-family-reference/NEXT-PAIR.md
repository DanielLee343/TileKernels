# 下一步：同平台最小配对预登记（离线草案）

目标是识别 G、N 与 MTE2 活动时间 A 的关系，不拟合模型、不设阈值。以下是待实现、待准入的开发实验，尚未采集。保持旧 8B/E1 样本和所有 C/H 留出封存；不改现有入口或现场数据。首选 950PR 物理卡 5、PCI `0000:E1:00.0`、CANN 9.2.0、TileKernels `c1cf914a82e6901c679445f872051ce44ac2cc63`，执行前重新核验设备映射及软件身份。两条件均沿用 E1 Default、应用预热 5、工具预热 5、kernel replay、工具管理 L2 清理及相同 profiler build；独立于 8B，不能用 8B 系数当 E1 标准。

## 配对 A：真实专家，尝试固定 N、改变 G

使用已归档 `norm_forward` D1 合同 BF16 x `[128,4096]`、weight `[4096]`、eps=1e-6、residual=None、out_scale=1、with_rstd=False。仅将输入行 stride 设为 4096 与 4112；两条件逻辑 x/weight 位值一致，输出均使用连续 `[4096,1]`、相同 dtype/shape 的 out，固定输出对象、布局和写路径。输入分别是具有不同布局的 backing/view，不可能同时是完全同一内存映射；保留同逻辑值、输入 base 地址 mod 128、输出对象与地址，记录完整地址映射及分配顺序。若环境不能可靠复用输出 allocation 或保持地址对齐，标记条件不满足。经独立完整输出/guard 准入，并核验实际 kernel、生成源码和 host/device binary，期望与 D1 已归档实现一致；不一致则本对不作为同代码比较。

源码依据：`../../expert-rule-todo5-20261106/p05-holdout-prep/replacement-screen/D1-device_kernel.asc` 的 weight 加载固定，x 加载以动态 `x_stride*2` 为行间距，写以独立的 `out_stride*2` 为行间距。源码表明只改变 x stride 可保持同静态写调用形式；不能推算实际动态请求、PMU G 或 N。现有 D1/D2 在一次双方未标记配对中 N 都是 200、G 相差 12,288 B，但它们同时改变输入和输出 stride，不证明本新对也会改变 G。先各做一次 Default 准入性观测：若实际 N 不相等或 G 相等，本对不满足目标，保留为不适用，不改 stride 追数值；满足后两条件各三次交错，顺序 A-B、B-A、A-B，所有次数和状态保留。准入观测和正式复采分开记录，均属开发数据。

D1/D2 已冻结的两轮配对补采是原联合输入/输出布局实验，不是本配对，也不是本实验的重复次数。现有 D3/D4 虽 N 同为 232，但 hidden、输入、工作量、形状均变；可作为已有线索，不能代替本对。

## 配对 B：固定 G、改变 N 的最短机制控制

现有已归档真实专家配置中，尚未发现能在同一逻辑对象、布局和写路径下预先确定固定 G 且改变 N 的合法参数对；G/N 为 Default 汇总，静态 copy 调用或 G/N 平均比值不能证明动态计数。不能拿 D3/D4 或假定拆分请求当已发现的专家对。

因此将 B 明确作为**独立微型机制控制，非 TileKernels 专家**：同一 BF16 输入、相同连续输出和逐元素复制合同、同一物理分配与相同有效字节集合，两个已审查的单 AIV 版本仅改变 GM→UB 的分段组织（一个大段、两个相邻小段），保持输出 UB→GM 的调用组织、访问区间、输出及其写路径一致；尺寸和分段取硬件 API 合法对齐值，实施前由生成源码及最终设备指令核实，不能凭源码宣称计数翻倍。具体尺寸、block 分工、合法性、产物、版本哈希须在任何 Default 数值出现前单独冻结；若无法让写路径和访问区间可审计地一致，就不执行或记不可用。两版本允许 device binary 不同（这是干预本身），输入输出 allocation、地址对齐、活动 block 和编译/运行条件尽量固定并记录。先各一次 Default 核验 G 相等且 N 不等、行键和活动 block 可比，失败即保留不适用，不搜索分段直到出现想要结果；通过后各三次交错 A-B、B-A、A-B。独立精度/guard 校验覆盖全部元素与未许可写区。该控制只回答可控载荷机制，不能冒充专家。

如果机制控制显示可区分，再单独冻结一个尚未使用、真实专家合法配置对，说明输入、布局、binary、实际 Default G/N 和写路径，随后作为新的开发实验验证；不能把微控制结果当作该专家预测或启用已封存 C/H。尚未找到这样的真实专家对，故此处不虚构配置或声称其已可运行。

## 可观察性与决策

每次保存唯一原始 Memory、PipeUtilization、OpBasicInfo、逐 block 行键、G/N/A、时间戳、输入哈希、地址对齐、source/device/host 哈希、完整命令和前后进程状态；结束快照未见进程不证明全程无竞争，有标记单列。核对同一计数窗口、输出正确性、实际布局及设备映射；缓存命中、动态请求形态、并发和精确指令事件无法由 Default 汇总保证相同，标为未知。A 是活动时间之和，不是端到端延迟。

对通过目标核验的对，逐轮报告原始 G、N、A 和配对差、中位数与每条件复采范围；不把复采当独立 case。若变化方向跨轮一致且差值相对复采范围明显，记作继续研究的线索；若差值落在波动内、方向反复或条件不成立，记为不确定或不适用，优先调查波动/合同而非调整模型。A 仅可说明该专家输入布局条件；B 仅可说明该受控实现，均不证明跨专家通用或单独归因。下一步若线索可复现，再冻结新真实专家测试；所有开发点均不得用于校准或宣称性能阈值。未观测结果不预设方向。
