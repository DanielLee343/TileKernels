# TODO 3A：现有 MTE2 数据的离线检查

## 结论

**在两组分别分析、case 等权的设置下，本轮检验的三种简单关系尚未形成可跨所测专家使用的稳定活动时间参考。** 本轮 3A 描述性分析和候选排查已完成；这些候选不进入阈值校准，尚未检验的条件化关系保留未知。以下数值是当前样本的观察或内部验证误差，不是性能标准。

## 范围与计算

仅使用 TODO 2 主池：0D 记录组 40 次、25 case、9 族；8B 记录组 32 次、32 case、2 族。两组各自分析，3 个重合 case 单列。设备记录不是物理序列号。每次有 56 条非零行；G、N、A、T 依次是 GM→UB 字节、MTE2 指令计数、MTE2 活动时间之和、AIV 时间之和。G 单位字节，A/T 单位微秒；G/A 单位字节/微秒，不是单个 block 或整机实测瞬时 GB/s。复采先对同 case 的各原始累计量求算术平均，再派生比值；每个 case 在拟合和验证中权重相同。全部采集和逐 block 原始量、来源与复采范围见 evidence.json；不把 72 次当作 72 个独立 case。

脚本重新读取 72 次采集各自的 Memory、PipeUtilization、OpBasicInfo，核对清单 SHA256（216 次文件引用）、行键、56 行正值、G/N/A/T 与 TODO 2 提取的一致性、源文件哈希和恒等式。G、N 来自 Memory，A、T 来自 PipeUtilization，跨表对应靠 block/sub-block 行键；这些是 Default 汇总，不是逐请求轨迹。计数窗口相同的证据来自 TODO 2 的跨表检查，不能据此证明逐事件同步或重叠。原记录为单 AIV、GM→UB、应用预热 5、kernel replay、工具管理 L2 清理；8B 缺完整运行时 stride，动态请求、缓存命中及竞争随时间的状态、物理卡映射仍未知。

## 按要求核对

1. **case 等权与复采：** 0D 的 9 个 case 有 2–3 次采集，其余只有 1 次；8B 每个 case 仅 1 次。0D 复采内 G、N 都不变，但 A 的极差/均值为 0.66%–57.68%，T 为 0.90%–26.80%。其中 mhc-expand-fwd 的 A 为 57.68%，说明单次活动表现可能不稳定；只有 2–3 次，不能估计稳健尾部分布。每个 case 的结果在 summary.json 的 replicates。
2. **依赖与不重复计分：** b=G/N，τ=A/N，BW=G/A=b/τ；同一累计窗口 G/T=(A/T)·BW。b 是每条计数指令平均搬运字节，不是实际请求大小分布；τ 是活动时间/指令的汇总比值，不是独立指令延迟。A/T 是活动占比的汇总比值。派生量共享分子分母，相关性不证明因果，也不能作为独立证据重复计分。
3. **请求组织与给定请求特征的表现：** 应分别观察 G、N、b 与 A、τ、BW；固定 b 的服务描述不能回答实现是否产生了不必要的请求或字节。0D b 的 case 中位数 303、范围 64.6–21341 字节/指令；8B 中位数 4337、范围 69.6–31909。两组内部 log(b) 与 log(τ) 相关系数分别 0.777、0.926，与 log(BW) 分别 0.624、0.722；这些探索性相关受共同 N/G、族和规模混杂，不能解释为 b 导致服务变化。
4. **条件覆盖：** 计量口径、预热/replay 与活动行数有证据，规模覆盖很宽；0D 的部分运行时布局已恢复，8B 布局不完整。72 份主池都有 L2 读侧六项汇总事件，dtype、规模和部分 stride 也有资料；这些条件本轮未用于建模。汇总的 G/N 不提供动态请求分布或具体指令组织，重放清理背景和 L2 汇总也不能提供逐请求命中匹配；仍缺时间分辨并发/重叠；56 行固定，没有不同活动 block 数对照。当前条件覆盖不足以判断低带宽是组织、缓存、规模、并发还是测量波动所致，不能据低点事后建专属条件。
5. **专家差异与跨组：** 三个重合 case 的源文件内容哈希和 kernel 名在两组一致，G、N 均相同；0D/8B 的 A 比值依次为 rmsnorm-supp-04 0.917、rmsnorm-supp-09 0.942、swiglu-supp-05 1.024，T 比值分别 1.073、1.250、0.993。0D 为两次均值，8B 只有一次；这不是严格配对或设备差异因果证明。源哈希和名字相同也不证明二进制、运行时布局、实际物理卡完全相同；故不合并绝对性能。
6. **候选比较和失败：** 用同一 case 等权的普通最小二乘，分别比较 A≈αN、A≈βG、A≈γ+αN+βG。每次留出整个 case 的所有复采，训练只用剩余 case；留族时训练排除整个目标族。报告按 case 的绝对相对误差中位数/P90；族偏差为该族有符号相对误差中位数，完整预测与误差在 evidence.json。0D 留 case：N 模型 886%/11857%，G 模型 56.7%/202.5%，三参数模型 166.9%/2981%，且 25 次中 14 次为负预测；0D 留族分别为 892.7%/4798.7%、56.7%/164.5%、144.4%/1916.9%，三参数 13 次负预测。8B 留 case：G 模型 30.7%/83.8%，三参数 52.4%/209.8%，三参数 11 次负预测；留族分别为 33.9%/86.0%、98.7%/3343.2%，三参数 16 次负预测。8B 只有两族，留族只是极有限的跨族外推检查。普通最小二乘最小化绝对时间平方误差，容易受大 case 影响；误差不是预注册的最终测试，不能据此选择可发布模型或给系数赋硬件成本含义。以 G 模型为例，0D 留 case 的 mhc_head 族中位有符号误差约 -85%，quant_cast_back 约 +142%；不仅是整体误差，还存在族方向偏差。N 模型和所有分组完整结果保留在机器证据中。
7. **逐 block：** 每次采集的 A 逐 block 变异系数在 0D 约 0.052–4.130、8B 约 0.011–3.829，说明聚合值会掩盖分布差异；这本身不能证明分布是预测误差的原因。逐 block 线性模型求和退化为 Mγ+αN+βG；M 恒为 56 时等同一个截距，未利用分布信息。当前没有独立证据选定分布特征作为新模型输入。

## 后续如何区分原因

先在同源、同输入、同设备记录和同样重放条件下，对代表不同族及规模的原 case 做交错重复，建立活动时间的波动范围；其中包括高波动 mhc-expand 与相对稳定的对照。再设计有机制依据的成对 case：尽量保持 G 与规模接近而改变指令组织，或保持请求组织近似而改变规模；记录编译产物、实际 stride、动态请求形态、缓存与并发背景。若交错重复仍有高波动，优先查测量/竞争；若同条件重复稳定而成对差异持续，再研究组织或规模影响。不同活动 block 数需额外受控样本。动态请求形态、有效请求区间和精确重复请求分析等待 TODO 3B；现有汇总关系、元数据检查及同口径 Default 复采和条件对照按各自证据要求推进，不依赖动态地址记录。这些是补证据建议，不是本次已运行的工作。
