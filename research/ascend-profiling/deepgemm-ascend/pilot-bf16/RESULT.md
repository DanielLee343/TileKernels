# BF16 普通 GEMM 小批试采结果

6/6 个 case 的采集程序和独立文件验收通过；每个 case 均保存 19 个 profiler 原始文件，共 114 个。它们均来自同一份 DeepGEMM-Ascend 源码，不能当成 6 个独立专家实现，也不能据此发布规则阈值。

输入是 BF16，`A[M,K] @ B[N,K].T`，无 bias/累加；参考为同一 BF16 输入的 CPU FP32 矩阵乘，再按输出 dtype 转换。上游相似度误差 `<1e-5` 及有限值检查通过。下表的最大绝对误差反映输出和参考之间存在的实际差异；相似度误差在 FP32 聚合下显示为 0，并不表示逐元素完全相等。

| M | N | K | 输出 | Op Type | 最大绝对误差 | 非零 Cube 活动行数 |
|---:|---:|---:|---|---|---:|---:|
| 1 | 576 | 7168 | BF16 | cube | 0 | 18 / 28 |
| 128 | 576 | 7168 | BF16 | cube | 0.5 | 27 / 28 |
| 1 | 32768 | 512 | BF16 | mix | 0.03125 | 28 / 28 |
| 128 | 7168 | 2048 | BF16 | cube | 0.5 | 28 / 28 |
| 1 | 256 | 7168 | FP32 | cube | 0.00018310546875 | 16 / 28 |
| 128 | 256 | 7168 | FP32 | cube | 0.000274658203125 | 24 / 28 |

“非零 Cube 活动行数”仅表示 `PipeUtilization.csv` 中 `aic_cube_time(us)>0` 的行数，不等于使用率、性能上限或加速空间。每个 case 的采集前和采集进程结束后输出哈希均一致；这不代表独立验算了 profiler 内部每次硬件重放的输出。

环境为 hidev Ascend 950PR、CANN 9.2.1，源码提交 `3a35326271b069b8b5bf1a754435acd6cc91575b`。独立环境使用 CANN 头文件兼容链接和 `-U__cpp_concepts` Bisheng 包装参数；详见 `environment.json`。**6 次 profile 都有 `kernel.json` 缺失及解析 magic 失败的警告**；虽然采集了所有原始表并匹配了 JIT 二进制，该警告对各指标的影响尚未独立确认。L2 状态也未独立验证。当前是采集可行性结果，不自动构成专家规则的正式准入。

`audit.json` 是 hidev 上独立验收记录；在任意有 Python 3 的机器运行 `python -B verify.py` 可核对归档合同和原始数据哈希。原始 `OpBasicInfo.csv`、7 组指标表、6 个 DeviceProf 文件、二进制和日志均在 `runs/` 下。
